Production hardening audit (2026-11-08)

The first hardening pass adds per-database concurrency admission, separate administrator admission, manifest/page structural validation, and expected-digest checks for memory-cache hits. All 27 Rust tests pass, including cancellation and adversarial stored-state cases. All 32 Pi 1.5.0 conformance tests pass with the updated test tooling. After updating the object-store/XML/TLS dependencies, versioned and unversioned MinIO qualification pass again. The publication algorithm and storage format are unchanged.

RustSec found two quick-xml denial-of-service advisories in the previous lockfile (RUSTSEC-2026-0194, RUSTSEC-2026-0195) and an unused default-feature path to unmaintained atomic-polyfill. Updating the object-store client and XML parser, and disabling unused postcard defaults, removes those findings. cargo-audit 0.22.2 reports zero vulnerabilities or warnings against advisory database commit 7a40350e1b8ba5b656d909f88222a8059a83d88d. The client test tools and documentation builder also had npm audit findings; their updated lockfiles report zero vulnerabilities. Fresh Rust and npm audits are now required Woodpecker gates outside Docker build caching. This is an advisory-database result, not an independent security review.

Initial local latency baseline

One release-build run on an AMD Ryzen AI Max+ 395 laptop, local filesystem with fsync, 1 KiB values, sequential operations. Other development work was active. This is an initial microbenchmark, not cloud performance or a throughput claim.

Operation Samples p50 p95 p99
Durable local write 200 13.962 ms 22.998 ms 25.913 ms
Cached local key read 2,000 0.313 ms 0.346 ms 0.486 ms

Reproduce with cargo run --locked --release --example bench using the pinned kache wrapper. The results expose an optimization target: synchronous publication and page rewriting currently dominate small writes. No B2/S3 latency numbers have been measured yet.
