Signing-key overlap and administrator migration

Current source builds support a bounded four-key verification ring with one active issuer, and token --admin now emits an expiring, domain-separated capability containing only expiration. Raw legacy key files preserve old administrator-envelope compatibility; new JSON keyrings disable it by default. Keyring creation refuses duplicates, more than four keys, malformed input, and file overwrite, and uses mode 0600 on Unix. A failed configuration does not quote key values in diagnostics. The rollout procedure separates binary upgrade, key expansion, issuer promotion, and retirement, and explicitly accounts for stale serving processes, offline issuers, legacy non-expiring envelopes, and clock skew.

The new finite model checks 1,189 states; both premature-promotion and premature-retirement controls produce counterexamples.
