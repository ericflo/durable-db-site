Understand

B2 storage and authority

B2 and S3 use the same native serving, publication, ownership and collection algorithms. Their wire bindings differ. The 1.0 operating scope qualifies B2 within one trust domain. AWS, sustained performance and broader topology faults remain follow-up qualification.

Authority without a separate coordinator#

B2’s native bucket update accepts ifRevisionIs; bucket listing returns its revision and metadata. This supplies conditional control updates without conditional file overwrites. The S3-compatible API carries immutable journals, tables, manifests and directory pages.

One durable-db-root bucket-info value identifies the shared B+tree directory and its checksum. Its entries are independent native partition control records. This respects B2’s metadata limits without a small database-count ceiling. A dedicated bucket holds one cluster prefix. Unrelated metadata is preserved; the adapter does not change lifecycle, public-access or retention settings.

Control-directory observations may be stale and are validated by a conditional barrier. Each replacement has a fresh mutation identity: live probes found that B2 can accept an identical-metadata no-op at a stale revision, while a genuinely different stale update returns conflict. The adapter never interprets the former as fresh authority.

Ordinary native database reads seal their results and validate the current writer’s permit using a fresh object GET. They do not conditionally update bucket metadata. Writes use immutable per-partition journals; acquisition, checkpoints, admission and shared metadata maintenance still use conditional publication. See the commit protocol and permit assumptions.

Physical collection#

Native and shared-directory collectors list candidates before fencing and delete only objects excluded from the protected state. B2 keeps file versions, so collection uses native b2_list_file_versions and b2_delete_file_version. S3-style delete markers would leave billed bytes behind. Work is bounded and retried in later sweeps; no external lifecycle policy may delete live database objects or prevent reclamation.

The shared directory uses pages of at most 64 entries/children and 64 KiB. Lookup/update follows a logarithmic path; listing and collection use bounded batches. Its root and reserved fields fit a 9,000-byte metadata budget. Unrelated bucket metadata can exhaust that budget and is rejected. These directory properties do not establish throughput for a large active tenant population.

Configuration#

For one cloud process on a laptop or behind a local proxy:

export B2_APPLICATION_KEY_ID=...   # service-side credential, never a tenant token
export B2_APPLICATION_KEY=...
durable-db serve --b2-bucket dedicated-private-bucket \
  --admin-key-file /run/secrets/admin.key \
  --upload-budget-bytes 1073741824 --upload-budget-attempts 100000

Multiple processes require the same layout, prefix, signing key and discovery service. The Kubernetes manifests supply a stable member ID, pod IP and headless-service name. Wildcard listeners require an explicit advertised IP. Prior cloud publication-engine namespaces require export with their original binary and restore into a fresh native namespace.

The key needs listBuckets, writeBuckets, readFiles, writeFiles, listFiles and deleteFiles for this bucket. Keep an account-wide provisioning key outside the database; mount only a bucket-scoped workload key. Authorization refreshes after expiration. Read-only bucket/version listings retry selected transient failures at most three times within a ten-second deadline, with jitter and bounded Retry-After. Conditional mutations remain uncertain on failure and are not replayed as fresh comparisons. Provider error guidance.

Evidence and limitations#

The verification results pin the native permit, forwarding, partition placement and CLI experiments to their source. Earlier format-3/5 publication-engine benchmarks and their failed contention runs remain historical evidence; they do not characterize the current native serving path.

Bucket metadata updates still serialize, and fresh permit GETs still have network cost. Independent journals remove the old bucket-wide publication requirement from ordinary data operations; they do not establish a production SLO. AWS qualification, sustained native load, complete tenant cost isolation and long-duration physical-growth checks are deferred beyond the scoped 1.0.
